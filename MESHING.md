# Meshing — the one-page map

**This workflow does not build your mesh. It ingests one, checks it hard, and hands the
building to a skill.**

Three of the four deck ingredients are a single well-defined transformation from raw data
to a NetCDF file, so they live in `deckbuild/`. Meshing is not: it is an interactive,
judgement-heavy craft, and the legacy tree has **eighteen** forked campaign folders to prove
it. No configuration file collapses those into one button.

What it does have is a written-down method. `skills/code-mesh-build-improve/SKILL.md`
encodes the whole pipeline, the acceptance gates, and — most valuable — the failures not to
repeat. Open it with Claude and work through your mesh.

## Who owns what

| Concern | Owner |
|:--|:--|
| `.msh` ↔ `.puml.h5` conversion | `deckbuild/mesh.py` |
| Acceptance gates A–G on a finished mesh | `deckbuild/mesh.py` |
| Stage F — is this mesh compatible with the deck? | `deckbuild/stage_f.py` |
| **Building a mesh from source geometry** | **the skill + Claude** |
| **Improving quality, refining to a spec** | **the skill + Claude** |

## The canonical workflow

```
A  source geometry -> clean fault surfaces   GOCAD/.ts/.inp -> per-strand STL; CGAL
                                             corefine if strands butt; trims/deepening
B  surface conditioning                      LEB refine to a max-edge target; feature-aware
                                             short-edge collapse; tetgen -d self-validate
                                               <- quality is WON here, not in the volume
C  volume fill                               tetgen -Y (rebuilds) or the gmsh hybrid route
                                             (from scratch, with topography)
D  volume cleanup                            mmg (NON-deterministic: take N draws, keep the
                                             best) -> de-sliver -> reorient negative tets
E  tags, PUML, gates                         SAFS tags -> msh_to_puml --validate
                                             -> fault-edge / conformity / quality gates
F  deck-compatibility verification           against the CONSUMING deck's actual ncs
```

## Three rules you will otherwise break

1. **Gmsh v2.2 ASCII only** (`-format msh22`). MFEM's reader has no v4 branch and
   mis-parses it, reporting the misleading `vertices indices are not unique`.
2. **Never move the fault surface.** Re-triangulating within a stated deviation tolerance is
   fine; changing strand shape or topology needs explicit approval.
3. **Work in a separate `meshing_<variant>/` folder** with `code/`, `results/` and
   `build_tmp/`. Never touch a production mesh folder in place.

## The gates this workflow runs

`MeshStage.verify` implements the legacy battery, names preserved:

| Gate | Check | Severity |
|:--|:--|:--|
| A | bbox, node/tet/fault-facet counts | report |
| B | fault edge max < the limit | HARD |
| C | BC round-trip: hull faces ×1, fault faces ×2 | HARD |
| D | inverted tets == 0 | HARD |
| E | volume resolution `f = Vs/dx >= gate` | HARD (needs a material nc; **skip ≠ pass**) |
| F | every fault facet inside the stress/friction/material hulls | HARD |
| G | receiver/pickpoint partition-boundary screen | WARN — heuristic |

Two of those deserve a note.

**D is not optional.** Gmsh does not guarantee tet orientation, and an inverted tet makes
SeisSol diverge with Inf/NaN bulk energy at t ≈ 1 s. `msh_to_puml` normalises orientation on
conversion and `--validate` asserts zero survive.

**E is non-monotone under refinement.** A 4× `Vs` step at the CVM's `z = -250 m` level plus
nearest-grid barycenter sampling means refining a mesh can *create* gate failures. Judge a
derived mesh by "introduces no NEW failures versus the frozen parent", not by an absolute
count.

## After your mesh exists

```python
from deckbuild.mesh import MeshStage
from deckbuild.stage_f import verify_mesh_against_deck

art = MeshStage().build(cfg, out, msh="my_mesh_safstags.msh")   # or ingest a .puml.h5
MeshStage().verify(cfg, art, material_nc=mat.material.path).print()

verify_mesh_against_deck(cfg, art.path, stress_nc=..., friction_nc=...,
                         material_nc=..., mu_s=0.6).print()
```

Then point `meshes.<name>.path` in your project descriptor at the `.puml.h5` and the rest of
the workflow picks it up.

## The demo mesh

`data/demo_planar/demo_planar.puml.h5` is a small worked instance: a vertical 60 × 15 km
strike-slip fault embedded in a tet slab, generated by `tools/make_demo_mesh.py`. It exists
so the demo project runs with zero downloads and no gmsh, and so section [2] of the workflow
has something real to ingest. It is deliberately coarse — it demonstrates the *pipeline*,
not a production resolution.
